# Retraining on deduplicated NF-v3 with corrected labels

Branch `feat/fair-comparison-corrected`. The protocol is the historical fair comparison
(30 s start-time windows, 32 edge features, identical models, trainer, thresholds and champion
rule; utilities pinned at `2262b53`). Three inputs can change:

1. **Duplicates removed.** A later row with the same `FLOW_START_MILLISECONDS` and 5-tuple as an
   earlier row is dropped (`utils/nfv3_dedup.py`). Copies never disagree on the label.
   Wednesday: 2,032,727 → 1,997,011 rows. Thursday: 2,147,533 → 2,085,579 rows.
2. **Labels.** `LABEL_MODE='corrected'` uses the Liu et al. rules (`utils/nfv3_relabel.py`).
   `LABEL_MODE='original'` keeps `Attack == 'Infilteration'`. Both targets are columns of the
   same deduplicated CSV, so the two modes have identical graphs except for `y`.
3. **Split.** `SPLIT_MODE='historical'` keeps the 70 % / 85 %-of-day cutoffs (16:51:52 and
   20:25:55 UTC, by window start). `SPLIT_MODE='episode'` uses 15:44 and 16:56 UTC instead, so each
   of the three corrected-positive episodes (14:33–15:30, 15:57–16:05, 17:46–18:38) falls in one
   split. With corrected labels the historical split leaves Test 1 without positives, so that
   combination is refused. The output bias is recomputed with the historical rule,
   logit(training-flow prevalence).

**Plan (2026-11-04).** The paper uses the historical split everywhere. The only GNN run is
**experiment 3**: original labels, duplicates removed, historical split, cells `M0_P0` and `M1_P0`
plus the MLP. It differs from the historical comparison only in the removed duplicates. These
are the notebook defaults.

Not run: the parameter-matched sensitivity cells and the external historical checkpoints
(Edge GRU replay, ST Uniform). Those were trained on the historical graphs.

Shared limitation (also in the historical runs): flows are assigned to windows by start time,
but their features are final flow statistics.

## Colab runs (experiment 3)

The notebooks in `code/python/notebook/*dedup*` are generated by
`code/python/scripts/derive_corrected_notebooks.py` from the historical notebooks. Edit the
generator and re-run it; do not edit the generated notebooks by hand.

Every notebook has `LABEL_MODE` and `SPLIT_MODE` at the top. The defaults (`original`,
`historical`) are experiment 3; keep them identical across the four notebooks.

1. `cic_ids2018_v3_graph_creation_dedup.ipynb`. On the first run it clones this branch and writes
   the deduplicated CSVs to `nids-mitre/data/cicids2018-v3-dedup/`. Then it builds
   `nids-mitre/dataset_processed_dedup_<split>_<label>/` (train/val/test, scaler,
   `build_manifest.json`, `ip_map.json`).
2. `cic_ids2018_v3_graph_creation_TEST2_dedup.ipynb`: builds
   `dataset_processed_thu0103_dedup_<split>_<label>/test2` with the Wednesday scaler of the same
   settings, and checks the Wednesday manifest.
3. `stgnn_factorial_dedup_colab.ipynb`. `RUN_CELLS=['M0_P0', 'M1_P0']`, `N_SEEDS=5` (3 is cheaper).
4. `baselines_dedup_colab.ipynb`. `RUN_MODELS=['MLP']`, `N_SEEDS` as in step 3.

Experiment 3 is 2 cells × 5 seeds + MLP × 5 seeds = 15 runs. Factor contrasts are computed only
when all four cells are present. Results go to
`results_stgnn_factorial_dedup_<split>_split_<label>_v1/` and
`results_baselines_dedup_<split>_split_<label>_v1/`. Training resumes from completed seeds.
`manifest.json` freezes the full protocol (four cells, five seeds, all baselines). `RUN_CELLS`,
`N_SEEDS` and `RUN_MODELS` only choose what a session trains. So a run can be extended in the same folder:
raise `N_SEEDS` or add cells, and completed runs are reused.
Champions and summary tables are recomputed over the session's seeds. In the baseline notebook,
`N_SEEDS` must not exceed the factorial's completed seeds.
