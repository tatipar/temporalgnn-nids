# Retraining on deduplicated NF-v3 with corrected labels

Branch `feat/fair-comparison-corrected`. The protocol is the historical fair comparison
(30 s start-time windows, 32 edge features, identical models, trainer, thresholds and champion
rule; utilities pinned at `2262b53`). Only three inputs change:

1. **Duplicates removed.** A later row with the same `FLOW_START_MILLISECONDS` and 5-tuple as an
   earlier row is dropped (`utils/nfv3_dedup.py`). Copies never disagree on the label.
   Wednesday: 2,032,727 → 1,997,011 rows. Thursday: 2,147,533 → 2,085,579 rows.
2. **Labels.** `LABEL_MODE='corrected'` uses the Liu et al. rules (`utils/nfv3_relabel.py`).
   `LABEL_MODE='original'` keeps `Attack == 'Infilteration'`. Both targets are columns of the
   same deduplicated CSV, so the two modes have identical graphs except for `y`.
3. **Split.** Wednesday windows are split by window start at 15:44 and 16:56 UTC (historical:
   70 % / 85 % of the day). The three corrected-positive episodes (14:33–15:30, 15:57–16:05,
   17:46–18:38) each fall in one split, so validation and Test 1 contain positives. The output
   bias is recomputed with the historical rule, logit(training-flow prevalence).

Not run: the parameter-matched sensitivity cells and the external historical checkpoints
(Edge GRU replay, ST Uniform). Those were trained on the historical graphs.

Shared limitation (also in the historical runs): flows are assigned to windows by start time,
but their features are final flow statistics.

## Option 1 — flow-level baselines (local, no GPU)

```bash
python3 code/python/scripts/prepare_corrected_inputs.py \
    cicids2018v3_wed2802.csv prepared/cicids2018v3_wed2802_dedup.csv \
    cicids2018v3_thu0103.csv prepared/cicids2018v3_thu0103_dedup.csv

    prepared/cicids2018v3_wed2802_dedup.csv prepared/cicids2018v3_thu0103_dedup.csv out/flow_baselines
```

Decision trees (depth 1/2/4/8) and logistic regression on the same 32 encoded features, trained on
Wednesday train only. Average precision on validation, Test 1 and Test 2, for both label sets.

## Colab runs (options 2 and 3)

The notebooks in `code/python/notebook/*dedup*` are generated by
`code/python/scripts/derive_corrected_notebooks.py` from the historical notebooks. Edit the
generator and re-run it; do not edit the generated notebooks by hand.

For each `LABEL_MODE`, set it at the top of each notebook:

1. `cic_ids2018_v3_graph_creation_dedup.ipynb`. On the first run it clones this branch and writes
   the deduplicated CSVs to `nids-mitre/data/cicids2018-v3-dedup/`. Then it builds
   `nids-mitre/dataset_processed_dedup_<mode>/` (train/val/test, scaler, `build_manifest.json`).
2. `cic_ids2018_v3_graph_creation_TEST2_dedup.ipynb`: builds
   `dataset_processed_thu0103_dedup_<mode>/test2` with the Wednesday scaler of the same mode.
3. `stgnn_factorial_dedup_episode_split_colab.ipynb`. Choose `RUN_CELLS` and `SEEDS`.
4. `baselines_dedup_episode_split_colab.ipynb`. `RUN_MODELS=['MLP']` by default.

| Plan | Mode | Factorial `RUN_CELLS` | Baselines | Seeds | Runs |
| --- | --- | --- | --- | --- | ---: |
| Option 2 (minimal) | corrected | `['M1_P1']` | MLP | 42, 123, 777 | 6 |
| Experiment 2 | corrected | all four | MLP | 5 | 25 |
| Experiment 3 | original | `['M0_P0', 'M1_P0']` | MLP | 5 | 15 |

Factor contrasts are computed only when all four cells are present. Results go to
`results_stgnn_factorial_dedup_episode_split_<mode>_v1/` and
`results_baselines_dedup_episode_split_<mode>_v1/`. Training resumes from completed seeds.
`manifest.json` freezes the full protocol (four cells, five seeds, all baselines). `RUN_CELLS`,
`N_SEEDS` and `RUN_MODELS` only choose what a session trains. So option 2 can be extended to
experiment 2 in the same folder: raise `N_SEEDS` and add cells, and completed runs are reused.
Champions and summary tables are recomputed over the session's seeds. In the baseline notebook,
`N_SEEDS` must not exceed the factorial's completed seeds.
